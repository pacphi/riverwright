# Riverwright Plan 2c: the adapter generator and the Claude Code plugin — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate every host's native adapter files from one source (`adapter-src/`), assemble the Claude Code plugin as a generated, committed `plugin/` folder with the repository root as its marketplace (ADR-0011), keep both honest with a drift check in CI so that `claude plugin validate --strict` passes on the marketplace and on the plugin, and make every generated hook carry `--home` and fire for shell tools only.

**Architecture:** `adapter-src/` holds host-neutral JSON: the plugin identity, the hook intents, the role list, the commands and the permission prefixes. `tools/generate-adapters.mjs` loads it (with the version from `package.json` and the role prompts from `roles/`), calls one renderer per host under `tools/adapters/`, appends a generated hook-dialect block to each `references/hosts/<host>.md`, and assembles `plugin/`: it copies the runtime sources named in `COPY_MAP` (`bin/`, `scripts/`, `templates/`, `skills/`, `roles/`, `references/` and `LICENSE`) byte for byte, and writes the Claude renderer's output (`plugin/.claude-plugin/plugin.json`, `plugin/hooks/hooks.json`, `plugin/agents/`, `plugin/commands/`, `plugin/settings/`) beside them. The repository root keeps only `.claude-plugin/marketplace.json`, whose one entry has `source: "./plugin"`. With `--check` the generator writes nothing and exits 1 when any output differs in content or executable bit, is a symlink, or is an orphan under `plugin/` or `.claude-plugin/`. Hook command lines come from Plan 2a's `launcherHookCommand`, rendered with a sentinel absolute root that is then replaced by `${CLAUDE_PLUGIN_ROOT}` (the installed copy of `plugin/`), so every quoting and `--home` check in 2a still runs. The sources, the tests and Plans 2a and 2b keep their root paths; `plugin/` is output only.

**Tech Stack:** Node.js 24+ built-ins only (`node:fs`, `node:path`, `node:url`, `node:util` `parseArgs`, `node:child_process` in tests, `node:test`, `node:assert`); the Claude Code CLI 2.1.285 for `claude plugin validate --strict` (development and CI only); GitHub Actions.

**Spec:** [`docs/specs/core-single-issue-pipeline.md`](../specs/core-single-issue-pipeline.md) §3.1 (layout), §7.2 (host hooks), §8 (roles), §12 (distribution and onboarding), §13 (adapter generation), §15 (tests), Appendix A (host hazards); [ADR-0002](../adr/0002-portable-skill-core-generated-adapters.md), [ADR-0003](../adr/0003-dependency-free-node-runtime.md), [ADR-0008](../adr/0008-never-overwrite-existing-repositories.md), [ADR-0010](../adr/0010-sealed-credential-released-by-human-unlock.md), [ADR-0011](../adr/0011-generated-plugin-folder-marketplace-at-root.md); host facts in [the evidence base](../research/evidence-base.md) §H and §I; layout evidence in [the plugin layout research](../research/plugin-layout.md) §3 and §6. Builds on [Plan 1](2026-09-29-plan-1-runtime.md), Plan 2a (security foundation, `docs/plans/2026-09-30-plan-2a-security-foundation.md`) and Plan 2b (skills, roles, templates, host references), treated as merged.

## Global Constraints

- Node.js 24 or newer; tests pass with `node --test` on ubuntu-latest, macos-latest and windows-latest, Node 24 and 26.
- **No npm dependencies.** The runtime (`scripts/`, `bin/`) and the generator (`tools/`) import only `node:` built-ins and relative files; a test enforces both.
- **ADR-0011: the root is only the marketplace.** `.claude-plugin/marketplace.json` at the repository root lists one plugin with `source: "./plugin"`, and there is no `plugin.json` at the root. `plugin/` is generated by `tools/generate-adapters.mjs` and committed, because a git marketplace installs what is in git; nobody edits it by hand. `.gitattributes` marks it `linguist-generated`, and `.markdownlint-cli2.jsonc` ignores it.
- **`plugin/` holds real files, never symlinks.** The generator refuses a symlinked source, and `--check` flags any symlink under `plugin/`.
- **Contributor material is never copied into `plugin/`:** `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `docs/`, `tests/`, `tools/`, `adapter-src/`, `.github/`, `package.json` and the lockfiles. The root `CLAUDE.md` stays where it is.
- **`plugin/` runs standalone.** Nothing in it reaches outside `plugin/` at run time; a test copies `plugin/` alone to a temporary directory and runs the launcher, the version command and the hook from there.
- Rendered files use LF line endings and end with one newline. Copied files are byte-identical to their sources: the `.cmd` launchers are CRLF by `.gitattributes` (`*.cmd text eol=crlf`) in both places, everything else is LF (`* text=auto eol=lf`), so the drift check means the same thing on every operating system. It compares bytes, and off Windows also the executable bit (`bin/riverwright` and `bin/rw` stay executable in `plugin/bin/`).
- One version source: `package.json` `version`. It is written into `plugin/.claude-plugin/plugin.json` `version` and into the marketplace entry's `version`. `claude plugin validate --strict .` compares the two: equal versions pass, and a mismatch fails ("At install time, plugin.json wins"), observed in Task 9.
- Every generated hook command comes from `launcherHookCommand(root, host, { home })` and carries `--home "account"`; it runs `bin/riverwright` through `/bin/sh`, so a missing Node exits 2 (deny).
- Generated hooks cover shell tools only: Claude Code matcher `Bash|PowerShell`.
- The generator never writes a root `.claude-plugin/plugin.json`, a root `hooks/`, `commands/`, `agents/` or `gemini-extension.json` (spec §3.1 gives those to the Gemini adapter in M4), or another host's manifest at the root or in `plugin/` (Review Focus 2).
- Host probes: `--version`, `--help`, and `--help` on subcommands listed in that host's `--help`. Never run `cursor agent`; never set `HERMES_HOME`; never run `grok plugin validate` (its help names a leader socket, so it may start a daemon) or `gemini hooks migrate` (it writes `.gemini/settings.json`).
- Nothing public: no push, pull request, comment, fork or marketplace listing. Adding a marketplace or installing the plugin on the owner's machine is a manual owner step (Task 9), never an executor step.
- Documentation layout (ADR-0001, `AGENTS.md`): plans in `docs/plans/`, guides in `docs/guides/`; never create `docs/superpowers/`. Run `pnpm lint:md` before committing any Markdown.
- Commit steps run only when the owner has asked for commits; otherwise stop after the tests pass and leave the changes for review. Commit messages never carry `Co-Authored-By`.

## Review Focus

These inputs follow from the specs but no earlier plan covers them; each has a test in the task named.

1. **The copy must not leak, and `plugin/` must run on its own.** A generated folder can quietly pick up a contributor file (a `CLAUDE.md` dropped into `skills/`, a symlink, a stray file left by a hand edit), or depend on something that only exists at the root: Plan 1's `scripts/lib/version.mjs` reads `../../package.json`, which is never copied, so `plugin/scripts/riverwright.mjs version` would crash in every install. The generator refuses contributor files and symlinks, `--check` flags orphans and hand edits, and a test copies `plugin/` alone to a temporary directory and runs `plugin/bin/riverwright version`, `plugin/scripts/riverwright.mjs version` and the generated hook command with `--home account` from there — Task 7 (version) and Task 8.
2. **Every other host would also load the plugin.** Codex, Cursor and Grok read `.claude-plugin/` and would also read their own manifests in `plugin/`; Gemini reads its manifest and `hooks/hooks.json` at the repository root. A second manifest or a root hook file would register the guard twice or change it — Task 8 (`assertNoForeignRoots`).
3. **Grok Build runs the Claude plugin's hook with a camelCase payload** (`toolInput.command`, `workspaceRoot`). Plan 1's `extractCommand` reads only snake case, so under Grok the command was unreadable — Task 2.
4. **Claude Code on Windows has a PowerShell tool.** A `Bash`-only matcher would let every PowerShell command through unguarded — Task 4 (matcher) and Task 2 (payload).
5. **Two manifests, one version, and a hook that cannot know the user's workspace.** The marketplace entry and `plugin/.claude-plugin/plugin.json` both carry the version, and `--strict` fails when they differ; a distributed hook cannot know the user's workspace path at generation time — Task 5 (one version) and Task 1 (symbolic `--home`).
6. **The publish exemption inside the plugin.** The guard exempts `riverwright submit` and `riverwright post` only when run through the trusted launcher, which `scripts/lib/commands/hook.mjs` resolves from its own location. In the plugin that is the plugin's own `bin/riverwright`, so the root checkout's launcher is not trusted by the plugin's hook — Task 8 proves both directions from a standalone copy.

## Decisions made

- **`--home account` (approved by the owner).** A plugin installed from a marketplace is written once, in this repository, for every user, so its hook cannot name the user's workspace. Plan 2a made `launcherHookCommand` require an absolute `home` and refuse `$`, so a hook's workspace is fixed when the hook is written and never read from the environment. The plugin's hook carries the symbolic `--home "account"`: the workspace under the account's home directory as the operating system records it (`os.userInfo().homedir`, the fallback 2a's `workspaceHomeFromArg` already has). It reads nothing from the environment, needs no configuration, and works in every host that loads the Claude plugin. A plugin option (`userConfig`) was rejected: it arrives as an environment variable, and under Grok it is unset, so every terminal command in Grok would be denied. Task 1 makes the small, additive change to two 2a functions; a user who moved their workspace with `RIVERWRIGHT_HOME` is not covered by the plugin hook until a later option adds a configured path.
- **The `plugin/` layout (ADR-0011).** The plugin is a generated, committed `plugin/` folder and the repository root is only the marketplace. The contributor `CLAUDE.md` stays at the root; in this layout it is outside the plugin, so strict validation passes without moving it.
- **The repository is `pacphi/riverwright`.** It is used in the manifests, the team-onboarding snippet and the install guide.

The rendered guard command, exactly as the prototype produced it:

```text
/bin/sh "${CLAUDE_PLUGIN_ROOT}/bin/riverwright" hook claude-code --home "account"
```

### Task 1: A symbolic `--home account` for distributed hooks

**Files:**

- Modify: `scripts/lib/paths.mjs`, `scripts/lib/exec.mjs`
- Test: `tests/account-home.test.mjs`

**Interfaces:**

- Consumes: `workspaceHomeFromArg(value, { userInfo })` and `launcherHookCommand(root, host, { platform, shell, home })` (Plan 2a).
- Produces: `ACCOUNT_HOME: 'account'` in `scripts/lib/paths.mjs`. `workspaceHomeFromArg('account', opts)` returns the same path as `workspaceHomeFromArg(undefined, opts)`. `launcherHookCommand(root, host, { home: ACCOUNT_HOME })` writes `--home "account"` for sh, cmd and PowerShell; every other `home` is still checked as an absolute, quotable path, and a missing `home` still throws `NO_HOME`.

- [ ] **Step 1: Write the failing test**

`tests/account-home.test.mjs`:

```js
import { test } from 'node:test';
import assert from 'node:assert/strict';
import path from 'node:path';
import { ACCOUNT_HOME, workspaceHomeFromArg } from '../scripts/lib/paths.mjs';
import { launcherHookCommand } from '../scripts/lib/exec.mjs';
import { callMain, tmpDir } from './helpers.mjs';

// Plan 2c (decided): a hook shipped in a marketplace plugin cannot know the user's workspace, so it
// carries the symbolic --home "account": the workspace under the account's home directory as the
// operating system records it. The environment is still never read.
const jane = { userInfo: () => ({ homedir: '/accounts/jane' }) };

test('ACCOUNT_HOME is the literal word account', () => {
  assert.equal(ACCOUNT_HOME, 'account');
});

test('--home account resolves from the account record, like an absent --home', () => {
  assert.equal(workspaceHomeFromArg('account', jane), path.join('/accounts/jane', '.riverwright'));
  assert.equal(workspaceHomeFromArg('account', jane), workspaceHomeFromArg(undefined, jane));
});

test('only the exact word is symbolic: look-alikes stay relative paths and are refused', () => {
  for (const bad of ['Account', 'account/', './account', ' account', 'accounts', '']) {
    assert.throws(() => workspaceHomeFromArg(bad, jane), /BAD_HOME|absolute/, JSON.stringify(bad));
  }
});

test('--home account still fails closed when the account has no home directory', () => {
  assert.throws(() => workspaceHomeFromArg('account', { userInfo: () => { throw new Error('no passwd entry'); } }), /--home/);
});

test('launcherHookCommand writes --home "account" for every shell and still refuses a missing home', () => {
  assert.equal(
    launcherHookCommand('/opt/rw', 'claude-code', { platform: 'darwin', home: ACCOUNT_HOME }),
    '/bin/sh "/opt/rw/bin/riverwright" hook claude-code --home "account"',
  );
  assert.equal(
    launcherHookCommand('C:\\rw', 'cursor', { platform: 'win32', home: ACCOUNT_HOME }),
    '"C:\\rw\\bin\\riverwright.cmd" hook cursor --home "account"',
  );
  assert.match(launcherHookCommand('C:\\rw', 'codex', { platform: 'win32', shell: 'powershell', home: ACCOUNT_HOME }), /hook codex --home "account"; if/);
  assert.throws(() => launcherHookCommand('/opt/rw', 'codex', { platform: 'linux' }), /NO_HOME|--home/);
  assert.throws(() => launcherHookCommand('/opt/rw', 'codex', { platform: 'linux', home: 'Account' }), /UNSAFE_PATH|absolute/);
});

test('the hook entry accepts --home account and allows a harmless command', async () => {
  const r = await callMain(['hook', 'claude-code', '--home', 'account'], {
    stdin: JSON.stringify({ hook_event_name: 'PreToolUse', tool_name: 'Bash', tool_input: { command: 'ls' }, cwd: tmpDir() }),
    cwd: tmpDir(),
  });
  assert.equal(r.code, 0, r.stderr);
});
```

`tools/adapters/source.mjs`:

```js
import fs from 'node:fs';
import path from 'node:path';
import { RiverwrightError } from '../../scripts/lib/errors.mjs';

// adapter-src/ is the single source for every host's adapter (spec §13). This module reads it, checks it,
// and adds the one version (package.json) and the role prompts (roles/<name>.md, written by Plan 2b).

export const HOOK_INTENTS = ['before-shell', 'session-start'];
export const ACCESS = ['read', 'edit'];
export const TIERS = ['small', 'default', 'strong'];
const ID = /^[a-z0-9]+(-[a-z0-9]+)*$/;

function fail(message) {
  throw new RiverwrightError('ADAPTER_SOURCE', `adapter-src: ${message}`);
}

function readJson(root, rel) {
  const file = path.join(root, rel);
  try {
    return JSON.parse(fs.readFileSync(file, 'utf8'));
  } catch (err) {
    return fail(`cannot read ${rel}: ${err.message}`);
  }
}

// Drops a leading YAML frontmatter block; the generator writes each host's own frontmatter.
export function roleBody(text) {
  const lf = String(text).replace(/\r\n/g, '\n');
  const m = /^---\n[\s\S]*?\n---\n/.exec(lf);
  return (m ? lf.slice(m[0].length) : lf).trim();
}

export function loadAdapterSource(root) {
  const pkg = readJson(root, 'package.json');
  if (typeof pkg.version !== 'string' || !/^\d+\.\d+\.\d+(-[0-9A-Za-z.-]+)?$/.test(pkg.version)) fail('package.json has no semver version');

  const plugin = readJson(root, 'adapter-src/plugin.json');
  if ('version' in plugin || 'version' in (plugin.marketplace ?? {})) fail('plugin.json must not carry a version; package.json is the only version source');
  if (!ID.test(plugin.name ?? '')) fail(`plugin name "${plugin.name}" must be kebab-case`);
  if (!ID.test(plugin.marketplace?.name ?? '')) fail(`marketplace name "${plugin.marketplace?.name}" must be kebab-case`);
  if (!plugin.author?.name || !plugin.marketplace?.owner?.name) fail('author.name and marketplace.owner.name are required');
  for (const key of ['description', 'homepage', 'repository', 'license']) {
    if (typeof plugin[key] !== 'string' || !plugin[key]) fail(`plugin.json needs "${key}"`);
  }

  const hooks = readJson(root, 'adapter-src/hooks.json');
  if (!Array.isArray(hooks)) fail('hooks.json must be an array');
  for (const h of hooks) {
    if (!ID.test(h.id ?? '')) fail(`hook id "${h.id}" must be kebab-case`);
    if (!HOOK_INTENTS.includes(h.intent)) fail(`hook "${h.id}" has unknown intent "${h.intent}" (use ${HOOK_INTENTS.join(', ')})`);
    if (!Number.isInteger(h.timeoutSeconds) || h.timeoutSeconds < 1 || h.timeoutSeconds > 60) fail(`hook "${h.id}" needs timeoutSeconds between 1 and 60`);
    if (h.intent === 'session-start' && !(Array.isArray(h.args) && h.args.length && h.args.every((a) => /^[a-z0-9-]+$/.test(a)))) {
      fail(`hook "${h.id}" needs args made of plain words`);
    }
  }
  if (hooks.filter((h) => h.intent === 'before-shell').length !== 1) fail('there must be exactly one before-shell hook');

  const agentList = readJson(root, 'adapter-src/agents.json');
  if (!Array.isArray(agentList)) fail('agents.json must be an array');
  const seen = new Set();
  const agents = agentList.map((a) => {
    if (!ID.test(a.role ?? '')) fail(`role "${a.role}" must be kebab-case`);
    if (seen.has(a.role)) fail(`role "${a.role}" is listed twice`);
    seen.add(a.role);
    if (!ACCESS.includes(a.access)) fail(`role "${a.role}" has unknown access "${a.access}"`);
    if (!TIERS.includes(a.tier)) fail(`role "${a.role}" has unknown tier "${a.tier}"`);
    if (typeof a.description !== 'string' || !a.description) fail(`role "${a.role}" needs a description`);
    const rel = `roles/${a.role}.md`;
    if (!fs.existsSync(path.join(root, rel))) fail(`${rel} is missing (Plan 2b writes the role prompts)`);
    const prompt = roleBody(fs.readFileSync(path.join(root, rel), 'utf8'));
    if (!prompt) fail(`${rel} is empty`);
    return { ...a, prompt };
  });

  const commands = readJson(root, 'adapter-src/commands.json');
  if (!Array.isArray(commands)) fail('commands.json must be an array');
  for (const c of commands) {
    if (!ID.test(c.name ?? '')) fail(`command name "${c.name}" must be kebab-case`);
    if (typeof c.description !== 'string' || typeof c.body !== 'string' || !c.body) fail(`command "${c.name}" needs a description and a body`);
  }

  const permissions = readJson(root, 'adapter-src/permissions.json');
  if (!Array.isArray(permissions.ask) || !permissions.ask.every((p) => /^[a-z][a-z0-9 -]*$/.test(p))) fail('permissions.json "ask" must list plain command prefixes');

  return { version: pkg.version, plugin, hooks, agents, commands, permissions };
}
```

```js
import { RiverwrightError } from '../../scripts/lib/errors.mjs';
import { launcherHookCommand } from '../../scripts/lib/exec.mjs';
import { ACCOUNT_HOME } from '../../scripts/lib/paths.mjs';

// A distributed plugin's hook cannot know its install root, so the command is rendered by Plan 2a's
// launcherHookCommand with a sentinel absolute root (every quoting and --home check still runs), and the
// sentinel is then replaced by the host's own placeholder, such as ${CLAUDE_PLUGIN_ROOT}.
export const SENTINEL_ROOT = '/RIVERWRIGHT_PLUGIN_ROOT_SENTINEL';

// A host placeholder: ${NAME} with an upper-case name, nothing a shell could re-parse inside double quotes
// beyond the variable itself.
const PLACEHOLDER = /^\$\{[A-Z][A-Z0-9_]*\}$/;
const WORD = /^[a-z0-9-]+$/;

export function pluginHookCommand(host, { rootPlaceholder, args, home = ACCOUNT_HOME } = {}) {
  if (!PLACEHOLDER.test(String(rootPlaceholder ?? ''))) {
    throw new RiverwrightError('UNSAFE_PLACEHOLDER', `root placeholder ${JSON.stringify(rootPlaceholder)} must look like \${NAME}`);
  }
  const rendered = launcherHookCommand(SENTINEL_ROOT, host, { platform: 'linux', shell: 'sh', home });
  let cmd = rendered;
  if (args !== undefined) {
    if (!Array.isArray(args) || !args.length || !args.every((a) => WORD.test(a) || /^--[a-z0-9-]+$/.test(a))) {
      throw new RiverwrightError('UNSAFE_ARG', 'launcher arguments must be plain words');
    }
    const at = rendered.indexOf(` hook ${host} `);
    cmd = `${rendered.slice(0, at)} ${args.join(' ')}`;
  }
  if (cmd.split(SENTINEL_ROOT).length !== 2) throw new RiverwrightError('SENTINEL', 'the rendered command must contain the root exactly once');
  return cmd.replace(SENTINEL_ROOT, rootPlaceholder);
}
```

Facts the renderer relies on (docs-only, code.claude.com/docs/en/plugins-reference, and `claude plugin validate --strict` in Task 9): a marketplace entry's relative `source` must start with `./`, and `./plugin` names a plugin in a subdirectory of the marketplace repository; `commands/`, `agents/`, `hooks/hooks.json` and `skills/` at the plugin root are loaded by default, so `plugin.json` names no component paths (a `hooks` key merges with the default file rather than replacing it, so naming the same file there is avoided); shell-form hooks reject `${user_config.*}`; `${CLAUDE_PLUGIN_ROOT}` is the installed copy of `plugin/` (the version-specific cache directory) and is substituted in hook commands and in command bodies; only `agent` and `subagentStatusLine` plugin settings take effect, so permission rules cannot ship in a plugin and `plugin/settings/` holds snippets, not a `settings.json`; `"shell": "bash"` makes Windows use Git Bash; a `timeout` that expires does not block (docs), so the guard's 30 seconds is generous rather than a lock. Observed with Claude Code 2.1.285 on a throwaway copy: a marketplace entry `version` equal to `plugin.json`'s passes `validate --strict .`, and a different one fails it.

```js
import { RiverwrightError } from '../../scripts/lib/errors.mjs';
import { HOST_ADAPTERS } from './hosts.mjs';
import { pluginHookCommand } from './hook-command.mjs';

// The Claude Code reference adapter (spec §13), laid out as ADR-0011 decides: the repository root is only the
// marketplace (one entry, source "./plugin"), and the plugin is the generated plugin/ folder. This renderer
// writes plugin/'s own files; the generator copies bin/, scripts/, skills/ and the other runtime sources
// beside them. Components sit in Claude's default folders (commands/, agents/, hooks/hooks.json, skills/),
// so plugin.json names none of them.

const ROOT_VAR = '${CLAUDE_PLUGIN_ROOT}';
export const PLUGIN_DIR = 'plugin';
const TOOLS = { read: 'Read, Grep, Glob, Bash', edit: 'Read, Grep, Glob, Bash, Edit, Write' };
const MODELS = { small: 'haiku', default: 'inherit', strong: 'opus' };

export const json = (value) => `${JSON.stringify(value, null, 2)}\n`;

// A single-line YAML scalar: quoted only when it has a character YAML would read specially.
function yamlLine(value) {
  const s = String(value);
  if (/[\r\n]/.test(s)) throw new RiverwrightError('ADAPTER_SOURCE', `frontmatter value must be one line: ${JSON.stringify(s)}`);
  return /^[\w(][^:#]*$/.test(s) && !/\s$/.test(s) ? s : JSON.stringify(s);
}

function githubRepo(url) {
  const m = /^https:\/\/github\.com\/([A-Za-z0-9._-]+\/[A-Za-z0-9._-]+?)(?:\.git)?\/?$/.exec(url);
  if (!m) throw new RiverwrightError('ADAPTER_SOURCE', `repository "${url}" is not a https://github.com/<owner>/<repo> URL`);
  return m[1];
}

export function renderClaude(src) {
  const files = new Map();
  const { plugin, version } = src;

  files.set(`${PLUGIN_DIR}/.claude-plugin/plugin.json`, json({
    name: plugin.name,
    displayName: plugin.displayName,
    version,
    description: plugin.description,
    author: plugin.author,
    homepage: plugin.homepage,
    repository: plugin.repository,
    license: plugin.license,
    keywords: plugin.keywords,
  }));

  // The entry carries the same version as plugin.json: `claude plugin validate --strict .` compares them and
  // fails on a mismatch ("At install time, plugin.json wins").
  files.set('.claude-plugin/marketplace.json', json({
    name: plugin.marketplace.name,
    owner: plugin.marketplace.owner,
    description: plugin.marketplace.description,
    plugins: [{ name: plugin.name, source: `./${PLUGIN_DIR}`, description: plugin.description, version }],
  }));

  const hooks = {};
  for (const h of src.hooks) {
    if (h.intent === 'before-shell') {
      hooks.PreToolUse = [{
        matcher: HOST_ADAPTERS['claude-code'].hook.matcher,
        hooks: [{ type: 'command', command: pluginHookCommand('claude-code', { rootPlaceholder: ROOT_VAR }), shell: 'bash', timeout: h.timeoutSeconds }],
      }];
    } else if (h.intent === 'session-start') {
      hooks.SessionStart = [{
        hooks: [{ type: 'command', command: pluginHookCommand('claude-code', { rootPlaceholder: ROOT_VAR, args: h.args }), shell: 'bash', timeout: h.timeoutSeconds }],
      }];
    }
  }
  files.set(`${PLUGIN_DIR}/hooks/hooks.json`, json({ hooks }));

  for (const a of src.agents) {
    files.set(`${PLUGIN_DIR}/agents/${a.role}.md`, [
      '---',
      `name: ${a.role}`,
      `description: ${yamlLine(a.description)}`,
      `tools: ${TOOLS[a.access]}`,
      `model: ${MODELS[a.tier]}`,
      '---',
      '',
      `<!-- Generated by tools/generate-adapters.mjs from roles/${a.role}.md and adapter-src/agents.json. Do not edit. -->`,
      '',
      a.prompt,
      '',
    ].join('\n'));
  }

  for (const c of src.commands) {
    files.set(`${PLUGIN_DIR}/commands/${c.name}.md`, [
      '---',
      `description: ${yamlLine(c.description)}`,
      '---',
      '',
      `<!-- Generated by tools/generate-adapters.mjs from adapter-src/commands.json. Do not edit. -->`,
      '',
      c.body.split('{{pluginRoot}}').join(ROOT_VAR),
      '',
    ].join('\n'));
  }

  // Plugins cannot ship permission rules (only "agent" and "subagentStatusLine" settings take effect), so
  // the ask rules are a snippet the user or `riverwright setup --project` adds to settings.
  files.set(`${PLUGIN_DIR}/settings/permissions.json`, json({
    permissions: { ask: src.permissions.ask.flatMap((c) => [`Bash(${c} *)`, `PowerShell(${c} *)`]) },
  }));

  files.set(`${PLUGIN_DIR}/settings/team-onboarding.json`, json({
    extraKnownMarketplaces: { [plugin.marketplace.name]: { source: { source: 'github', repo: githubRepo(plugin.repository) } } },
    enabledPlugins: { [`${plugin.name}@${plugin.marketplace.name}`]: true },
  }));

  return files;
}
```

// and the adapters cannot disagree, and the drift check covers both.
export const REFERENCE_SLUG = 'riverwright-generated-hooks';

const cell = (s) => String(s).replace(/\|/g, '\\|');
const code = (s) => `\`${cell(s)}\``;

function hookCommandFor(host, status) {
  if (status === 'generated' || status === 'relies-on-claude') {
    return pluginHookCommand('claude-code', { rootPlaceholder: '${CLAUDE_PLUGIN_ROOT}' });
  }
  return launcherHookCommand(SENTINEL_ROOT, host, { platform: 'linux', shell: 'sh', home: ACCOUNT_HOME })
    .replace(SENTINEL_ROOT, '${RIVERWRIGHT_ROOT}');
}

export function renderHostReferenceBlock(host) {
  const a = hostAdapter(host);
  const h = a.hook;
  const matcher = h.matcher ? `${code(h.matcher)} (${cell(h.matcherNote)})` : `none claimed: ${cell(h.matcherNote)}`;
  const command = hookCommandFor(host, a.status);
  const lines = [
    '## Hook dialect',
    '',
    `Generated by \`tools/generate-adapters.mjs\` from \`tools/adapters/hosts.mjs\`. Edit that file, not this block. Checked against ${cell(host)} ${cell(a.version)}.`,
    '',
    '| Item | Value |',
    '|---|---|',
    `| Status in Plan 2c | ${a.status}: ${cell(a.reason)} |`,
    `| Event | ${code(h.event)} |`,
    `| Shell-tool matcher | ${matcher} |`,
    `| Command field | ${code(h.commandField)} |`,
    `| Deny | ${cell(h.deny)} |`,
    `| On crash or timeout | ${cell(h.onFailure)} |`,
    `| Evidence | ${h.label} |`,
    `| Hook command | ${code(command)} |`,
    '',
  ];
  if (host === 'hermes-agent') {
    lines.push(
      'Hermes plugins cannot ship shell hooks. The user adds this entry to `~/.hermes/config.yaml` themselves, with `${RIVERWRIGHT_ROOT}` replaced by the absolute path of their Riverwright install, and consents to it on first use. Riverwright never writes this file.',
      '',
      '```yaml',
      'hooks:',
      '  pre_tool_call:',
      '    - matcher: terminal',
      `      command: ${command}`,
      '      timeout: 20',
      '      fail_closed: true',
      '```',
      '',
    );
  }
  lines.push('## Action-to-tool map', '', '| Action | Tool | Evidence |', '|---|---|---|');
  for (const [action, tool, label] of a.actions) lines.push(`| ${cell(action)} | ${cell(tool)} | ${label} |`);
  return lines.join('\n');
}

export function renderHostReference(host, existingText) {
  return upsertBlock(existingText, REFERENCE_SLUG, renderHostReferenceBlock(host)).text;
}

How the generator decides (ADR-0011): rendered files are written as UTF-8 text with LF endings; copied files are the source's bytes, so the `.cmd` launchers keep the CRLF that `.gitattributes` gives them in both places. A copied source that the generator also renders (`references/hosts/*.md`) is copied as rendered, so one run leaves both consistent. A file is current only when it is a regular file (not a symlink) with the same bytes and, off Windows, the same executable bit. Anything under `plugin/` or `.claude-plugin/` that the generator does not write is an orphan: `--check` names it, write mode deletes it. `LICENSE` is copied because the MIT license asks for its notice in every copy; `LICENSE` is not contributor material.

The publish exemption (Review Focus 6): `TRUSTED_LAUNCHER` is resolved from `scripts/lib/commands/hook.mjs`'s own location, so the hook that runs from `plugin/` trusts `plugin/bin/riverwright`, `plugin/bin/riverwright.cmd` and `plugin/scripts/riverwright.mjs`, the files `${CLAUDE_PLUGIN_ROOT}/bin/riverwright` names, and not a checkout's `bin/riverwright`; the checkout's hook trusts only the checkout's launcher. No code changes for this; `tests/plugin-standalone.test.mjs` pins it in both directions.

```js
#!/usr/bin/env node
// Renders adapter-src/ into each host's native files and assembles the generated plugin/ folder (spec §13,
// ADR-0011). Development tool; Node built-ins only.
//   node tools/generate-adapters.mjs            write the files
//   node tools/generate-adapters.mjs --check    exit 1 if any generated file is stale (CI)
import fs from 'node:fs';
import path from 'node:path';
import { fileURLToPath } from 'node:url';
import { parseArgs } from 'node:util';
import { RiverwrightError } from '../scripts/lib/errors.mjs';
import { HOSTS } from '../scripts/lib/hosts.mjs';
import { loadAdapterSource } from './adapters/source.mjs';
import { HOST_ADAPTERS } from './adapters/hosts.mjs';
import { renderClaude, PLUGIN_DIR } from './adapters/claude-code.mjs';
import { renderHostReference } from './adapters/references.mjs';

// One renderer per host. A stub renders nothing yet; its facts still reach references/hosts/<host>.md.
export const RENDERERS = {
  'claude-code': renderClaude,
  codex: () => new Map(),
  'gemini-cli': () => new Map(),
  cursor: () => new Map(),
  'grok-build': () => new Map(),
  'hermes-agent': () => new Map(),
};

// The runtime sources copied into plugin/, byte for byte (ADR-0011). They stay at the root, where the tests and
// the other plans use them; plugin/ is output only. adapter-src/ is an input to the renderers, never copied.
export const COPY_MAP = [
  ['bin', `${PLUGIN_DIR}/bin`],
  ['scripts', `${PLUGIN_DIR}/scripts`],
  ['templates', `${PLUGIN_DIR}/templates`],
  ['skills', `${PLUGIN_DIR}/skills`],
  ['roles', `${PLUGIN_DIR}/roles`],
  ['references', `${PLUGIN_DIR}/references`],
  ['LICENSE', `${PLUGIN_DIR}/LICENSE`],
];

// Contributor material never reaches a user's plugin cache (ADR-0011, point 4): by file name anywhere in
// plugin/, and by top-level folder.
export const CONTRIBUTOR_FILES = ['CLAUDE.md', 'AGENTS.md', 'GEMINI.md', 'package.json', 'package-lock.json', 'pnpm-lock.yaml', 'yarn.lock', 'npm-shrinkwrap.json'];
export const CONTRIBUTOR_DIRS = ['docs', 'tests', 'tools', 'adapter-src', '.github', 'node_modules'];

// Operating-system clutter that is never copied and never counts as an orphan (.gitignore ignores it too).
const CLUTTER = new Set(['.DS_Store', 'Thumbs.db']);

// Directories the generator owns completely: a file in them that it no longer writes is stale.
export const OWNED_DIRS = ['.claude-plugin', PLUGIN_DIR];

// Outputs another host would also load. The root .claude-plugin/ holds only the marketplace (ADR-0011). A root
// hooks/, commands/, agents/ or gemini-extension.json belongs to the Gemini extension (spec §3.1, M4). Codex,
// Cursor and Grok read the Claude plugin, so their own manifests, at the root or in plugin/, would register a
// second plugin or a second guard (spec §13: never both).
export const FORBIDDEN_OUTPUTS = [
  '.claude-plugin/plugin.json', 'hooks/', 'commands/', 'agents/', 'gemini-extension.json',
  '.codex-plugin/', '.cursor-plugin/', '.grok-plugin/',
  `${PLUGIN_DIR}/.codex-plugin/`, `${PLUGIN_DIR}/.cursor-plugin/`, `${PLUGIN_DIR}/.grok-plugin/`, `${PLUGIN_DIR}/gemini-extension.json`,
];

export function assertNoForeignRoots(paths) {
  for (const p of paths) {
    const hit = FORBIDDEN_OUTPUTS.find((f) => (f.endsWith('/') ? p.startsWith(f) : p === f));
    if (hit) throw new RiverwrightError('FOREIGN_ROOT', `${p} would also be loaded by another host (${hit}); M4 decides where that host's adapter lives`);
  }
}

export function assertNoContributorFiles(paths) {
  for (const p of paths) {
    if (!p.startsWith(`${PLUGIN_DIR}/`)) continue;
    const parts = p.split('/').slice(1);
    if (CONTRIBUTOR_FILES.includes(parts.at(-1)) || CONTRIBUTOR_DIRS.includes(parts[0])) {
      throw new RiverwrightError('CONTRIBUTOR_FILE', `${p} is contributor material and must never be copied into ${PLUGIN_DIR}/ (ADR-0011)`);
    }
  }
}

// Every file under a root source, as posix paths relative to the root. A symlink is refused: plugin/ holds
// real files only, and following a link could pull in something outside the source.
function sourceFiles(root, rel) {
  const abs = path.join(root, ...rel.split('/'));
  let st;
  try {
    st = fs.lstatSync(abs);
  } catch {
    throw new RiverwrightError('MISSING_SOURCE', `${rel} is missing; it is copied into ${PLUGIN_DIR}/`);
  }
  if (st.isSymbolicLink()) throw new RiverwrightError('SYMLINK_SOURCE', `${rel} is a symlink; ${PLUGIN_DIR}/ holds real files only`);
  if (st.isFile()) return [rel];
  return fs.readdirSync(abs).filter((n) => !CLUTTER.has(n)).sort().flatMap((n) => sourceFiles(root, `${rel}/${n}`));
}

// Everything the generator writes: path -> { data: Buffer, executable: boolean }.
export function renderAll(root) {
  const src = loadAdapterSource(root);
  const files = new Map();
  const put = (rel, data, executable = false) => {
    if (files.has(rel)) throw new RiverwrightError('DUPLICATE_OUTPUT', `${rel} is written twice`);
    files.set(rel, { data: Buffer.isBuffer(data) ? data : Buffer.from(data, 'utf8'), executable });
  };
  for (const host of HOSTS) {
    for (const [p, text] of RENDERERS[host](src)) put(p, text);
  }
  for (const host of HOSTS) {
    const rel = `references/hosts/${host}.md`;
    const file = path.join(root, ...rel.split('/'));
    if (!fs.existsSync(file)) throw new RiverwrightError('MISSING_REFERENCE', `${rel} is missing (Plan 2b creates it with the host's safe probes)`);
    put(rel, renderHostReference(host, fs.readFileSync(file, 'utf8')));
  }
  // Copies come last, so a source the generator also writes (references/hosts/*.md) is copied as rendered.
  for (const [from, to] of COPY_MAP) {
    for (const rel of sourceFiles(root, from)) {
      const target = to + rel.slice(from.length);
      const abs = path.join(root, ...rel.split('/'));
      const data = files.has(rel) ? files.get(rel).data : fs.readFileSync(abs);
      put(target, data, (fs.statSync(abs).mode & 0o111) !== 0);
    }
  }
  const paths = [...files.keys()];
  assertNoForeignRoots(paths);
  assertNoContributorFiles(paths);
  return files;
}

// Every entry under the owned directories, symlinks included (never followed).
function listOwned(root) {
  const out = [];
  const walk = (rel) => {
    const abs = path.join(root, ...rel.split('/'));
    if (!fs.existsSync(abs)) return;
    for (const e of fs.readdirSync(abs, { withFileTypes: true })) {
      if (CLUTTER.has(e.name)) continue;
      const child = `${rel}/${e.name}`;
      if (e.isDirectory()) walk(child);
      else out.push(child);
    }
  };
  for (const d of OWNED_DIRS) walk(d);
  return out;
}

const WINDOWS = process.platform === 'win32';

// Current when the path is a regular file (not a symlink) with the same bytes and, off Windows, the same
// executable bit.
function isCurrent(abs, { data, executable }) {
  let st;
  try {
    st = fs.lstatSync(abs);
  } catch {
    return false;
  }
  if (!st.isFile()) return false;
  if (!WINDOWS && ((st.mode & 0o111) !== 0) !== executable) return false;
  return fs.readFileSync(abs).equals(data);
}

export function generate({ root, check = false }) {
  const files = renderAll(root);
  const stale = [];
  const written = [];
  for (const [rel, entry] of files) {
    const abs = path.join(root, ...rel.split('/'));
    if (isCurrent(abs, entry)) continue;
    stale.push(rel);
    if (!check) {
      fs.rmSync(abs, { recursive: true, force: true });
      fs.mkdirSync(path.dirname(abs), { recursive: true });
      fs.writeFileSync(abs, entry.data);
      if (!WINDOWS) fs.chmodSync(abs, entry.executable ? 0o755 : 0o644);
      written.push(rel);
    }
  }
  for (const rel of listOwned(root)) {
    if (files.has(rel)) continue;
    stale.push(rel);
    if (!check) fs.rmSync(path.join(root, ...rel.split('/')), { force: true });
  }
  stale.sort();
  written.sort();
  const statuses = HOSTS.map((h) => ({ host: h, status: HOST_ADAPTERS[h].status }));
  return { stale, written, statuses };
}

export function main(argv, io = process) {
  const { values } = parseArgs({ args: argv, options: { check: { type: 'boolean' }, root: { type: 'string' } } });
  const root = path.resolve(values.root ?? path.join(path.dirname(fileURLToPath(import.meta.url)), '..'));
  const r = generate({ root, check: Boolean(values.check) });
  for (const s of r.statuses) io.stdout.write(`${s.host}: ${s.status}\n`);
  if (values.check) {
    if (!r.stale.length) {
      io.stdout.write('generated files are up to date\n');
      return 0;
    }
    for (const p of r.stale) io.stderr.write(`stale: ${p}\n`);
    io.stderr.write(`Generated files (${PLUGIN_DIR}/, .claude-plugin/, references/hosts/) are out of date. Do not edit ${PLUGIN_DIR}/ by hand. Run: node tools/generate-adapters.mjs\n`);
    return 1;
  }
  io.stdout.write(`wrote ${r.written.length} file(s)\n`);
  return 0;
}

if (process.argv[1] && path.resolve(process.argv[1]) === fileURLToPath(import.meta.url)) {
  try {
    process.exitCode = main(process.argv.slice(2));
  } catch (err) {
    process.stderr.write(`generate-adapters: ${err.message}\n`);
    process.exitCode = 2;
  }
}
```

````markdown
# Install Riverwright

Riverwright is pre-release. This guide covers what exists: the Claude Code plugin, installed from this
repository, which is its own marketplace. The other hosts are listed with what is known about them today.
Nothing here changes a repository you work in; runs live in `~/.riverwright`.

Requirements: Node.js 24 or newer, `git`, `gh` (authenticated), and one supported host.

## Claude Code

```bash
claude plugin marketplace add pacphi/riverwright
claude plugin install riverwright@riverwright
```

In a session, `/plugin install riverwright@riverwright` does the same. While the plugin is enabled, `riverwright`
and its short alias `rw` are on the Bash tool's PATH. Run `/riverwright:doctor` to check the machine.

The install copies only this repository's `plugin/` folder into Claude Code's plugin cache: the launcher, the
runtime, the skills, the roles, the templates and the host references. The documentation, the tests and the
contributor instructions stay out of it. Claude Code records the install in the settings file of the scope you
choose (`enabledPlugins`); nothing is written to your own `CLAUDE.md`.

The plugin adds one guard hook. It runs before every Bash and PowerShell tool call, reads nothing but the
command, and denies public actions (push, pull request, comment, fork) inside your Riverwright workspace
unless they go through `riverwright submit` or `riverwright post` run by the launcher's full path
(`${CLAUDE_PLUGIN_ROOT}/bin/riverwright submit`); a bare `riverwright submit` from an agent is blocked
there, and so is the `rw` alias. The hook does not see commands you type in your own terminal. It guards
the workspace under your account's home directory (`~/.riverwright`). Details: [Claude Code reference](../../references/hosts/claude-code.md).

Limits:

- On Windows, Claude Code runs the hook with Git Bash. Without Git Bash the hook cannot start, and Claude
  Code treats that as "allow"; the git pre-push guard in each clone still stops the push.
- claude.ai and Cowork do not install plugins that ship a `bin/` directory. Use the Claude Code CLI or the
  desktop app.
- If you moved your workspace with `RIVERWRIGHT_HOME`, the plugin's hook still guards `~/.riverwright`.

### Ask before approvals and public steps

A plugin cannot ship permission rules. To have Claude Code ask before `riverwright approve`, `submit` and
`post`, add this to your `~/.claude/settings.json` (or a project's `.claude/settings.json`) yourself:

```json
{
  "permissions": {
    "ask": [
      "Bash(riverwright approve *)",
      "PowerShell(riverwright approve *)",
      "Bash(rw approve *)",
      "PowerShell(rw approve *)",
      "Bash(riverwright submit *)",
      "PowerShell(riverwright submit *)",
      "Bash(rw submit *)",
      "PowerShell(rw submit *)",
      "Bash(riverwright post *)",
      "PowerShell(riverwright post *)",
      "Bash(rw post *)",
      "PowerShell(rw post *)"
    ]
  }
}
```

### Team onboarding

A repository can prompt its contributors to install the plugin. Add this to the repository's
`.claude/settings.json`, or let `riverwright setup --project` add the keys that are absent:

```json
{
  "extraKnownMarketplaces": {
    "riverwright": {
      "source": {
        "source": "github",
        "repo": "pacphi/riverwright"
      }
    }
  },
  "enabledPlugins": {
    "riverwright@riverwright": true
  }
}
```

The marketplace registers after the contributor accepts the workspace trust dialog.
````
